# Security

Security and privacy are fundamental to the VerixID architecture.

VerixID is designed around cryptographic verification, zero-custody file processing, deterministic verification, and independent verification.

## Reporting a Vulnerability

If you discover a security vulnerability affecting VerixID, please report it responsibly.

**Do not open a public GitHub issue for sensitive security vulnerabilities.**

Please contact:

**[security@verixid.com](mailto:security@verixid.com)**

When reporting a vulnerability, please provide enough information to reproduce and understand the issue, including where applicable:

* A description of the vulnerability
* The affected component or endpoint
* Steps to reproduce the issue
* Potential security impact
* Any relevant logs, requests, or proof of concept

Please avoid including sensitive personal information or confidential data in the report.

## Security Documentation

For VerixID's security architecture, privacy model, and security information, see:

https://verixid.com/security/

## Responsible Disclosure

We ask security researchers and users to avoid publicly disclosing sensitive vulnerability details before the issue has been reviewed and, where appropriate, addressed.

VerixID appreciates responsible security research that helps improve the security and reliability of the service.

## Scope

This repository contains public documentation and related resources for VerixID.

For vulnerabilities involving the production service, API, authentication, or infrastructure, please use the security contact above rather than opening a public GitHub issue.
